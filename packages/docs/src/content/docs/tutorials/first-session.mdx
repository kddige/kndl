In this tutorial you run the whole of claude-hub on one machine: a Hub, the web UI and one Runner. You sign in without GitHub, give a Repo its Environment, start a Session on it, and see a second person join. It takes about twenty minutes, most of it waiting for the first Build.

:::note[From a checkout]
This tutorial runs claude-hub from a checkout of its repository with `bun run`, so you see each part start. To install a Hub and Runner as services instead, use the `claude-hub` command: see [Install claude-hub](/how-to/install/).
:::

## What you need

- **A Mac with Apple Silicon, or Linux with KVM.** Sandboxes are [microsandbox](https://github.com/microsandbox/microsandbox) microVMs, which need one of the two. microsandbox itself comes with `bun install`.
- **[Bun](https://bun.sh) 1.4 or newer.**
- **Claude Code**, as `claude` on your `PATH`, signed in. Run `claude` once and sign in if you never have: every Session on this machine uses that login.
- **git**.
- **A GitHub repository to work on** that this machine's own git can clone over HTTPS, such as one of yours. Without the GitHub App, the Runner clones with your host's git credentials.

## Start the Hub

<Steps>

1. Get the code and install its dependencies:

   ```sh
   gh repo clone kddige/claude-hub
   cd claude-hub
   bun install
   ```

2. Build the web UI, so the Hub can serve it:

   ```sh
   bun run web:build
   ```

3. Start the Hub with dev login, which signs you in without GitHub. It only works when the Hub and its URL are both on loopback:

   ```sh
   HUB_PUBLIC_URL=http://127.0.0.1:7777 CLAUDE_HUB_DEV_LOGIN=1 bun run hub
   ```

   The Hub logs a few warnings at startup: GitHub sign-in is off, the GitHub App is not configured, `HUB_SECRETS_KEY` is not set, and dev login is on. All of them are expected here. Leave it running.

</Steps>

## Start a Runner

<Steps>

1. In a second terminal, in the same checkout, issue a Runner token for this machine:

   ```sh
   bun run runner-token "$(hostname -s)"
   ```

   It prints a token that starts with `chr_`. It is shown once, so copy it now.

2. Start the Runner with that token:

   ```sh
   RUNNER_TOKEN=chr_… bun run runner
   ```

   `bun run runner` builds the `hub-link` mod first, then connects to the Hub at `http://127.0.0.1:7777`.

</Steps>

## Sign in

Open [http://127.0.0.1:7777](http://127.0.0.1:7777). Under **Dev login**, type a name, such as `alice`, and press **Sign in as dev**. You land on the Hub's home, with an empty sidebar.

## Give your Repo an Environment

Every Repo needs an Environment before its first Session: the recipe its Sandboxes are built from.

<Steps>

1. Press **New Session** (the plus button at the top of the sidebar).

2. In **Repo**, enter your repository as `owner/name`. In **Base branch**, enter the branch Claude should start from, such as `main`. Leave **Runner** on **Any online Runner**, and press **Start Session**.

3. The Repo has no Environment yet, so the web UI takes you to its Environment screen, under a banner that says your Session starts once one is applied. The draft holds the defaults: Debian with the usual build tools (`buildpack-deps:bookworm`), no scripts, no Docker, 2 CPUs and 4 GiB of memory. Leave them for now.

4. Under **Apply**, pick your Runner in **Runner to build on** and press **Test build**. Its log streams in below. The first one pulls the image, so it takes a few minutes.

5. When it passes, press **Apply and start Session**. The draft becomes the Environment's version 1, and your Session starts.

</Steps>

## Work in the Session

The Session opens with a **Starting…** banner. The Runner clones your Repo onto a new Work branch, builds the Environment for itself the first time, boots the Session's Sandbox and starts Claude Code. **Show log** in the banner follows along.

<Steps>

1. Send a prompt, such as:

   > List the files in this repository and tell me what it does.

   Claude's reply streams into the transcript, with each tool call it makes. Claude Code and its tools run in the Sandbox, on the Workspace mounted at `/workspace`, not on your machine.

2. Open the **Terminal** tab. It mirrors Claude Code's own screen, live. You can type into it, which is how you answer a dialog the chat doesn't show.

3. Open [http://127.0.0.1:7777](http://127.0.0.1:7777) in a private window, and sign in with dev login as someone else, such as `sam`. Open the same Session from the sidebar. Both windows show the same transcript; a prompt `sam` sends while Claude is busy waits in the Prompt queue for its turn.

</Steps>

## Stop

Press Ctrl-C in the Runner's terminal, then in the Hub's. The Session is Frozen while the Runner is gone. Its Claude Code runs on in its Sandbox, so when you start both again the Session is Active as it was, and takes prompts at once. Left alone, an idle Session goes to sleep after 15 minutes and wakes on the next prompt.
