Start a Session on a Repo, drive it while your team watches, and get its work onto GitHub.

## What you need

- An account on a Hub with at least one online Runner.
- At least one Model of your own: a [Connected provider](/guides/connect-your-providers/), or your [Claude credential](/guides/add-your-claude-credential/) for Claude's Models, on your **Account** page. The Sessions you start run on them.
- A Repo with an [Environment](/guides/set-up-an-environment/). Starting the first Session on a Repo takes you there.

## Start a Session

<Steps>

1. Press **New Session**, at the top of the sidebar.

2. Pick the **Repo**, or type it as `owner/name`. **Branch** fills in with the Repo's default branch.

3. Choose where the agent commits:
   - Leave **Work on a new branch** on to commit to a new branch, `claude/<session id>`.
   - Turn it off to commit to the branch itself.
   - Type a new name and pick **Create branch '…'** to start a branch of your own.

4. Leave **Runner** on **Any online Runner**.

5. In **Model**, pick one of your Models, grouped by Provider. With a Claude credential, it starts on Claude's first Model. Without one, it starts on your first. Press the thinking button beside it to set a [Thinking level](/guides/manage-a-session/#choose-the-model-and-thinking-level).

6. Press **Start Session**.

   The Session opens with a **Starting…** banner. **Show log** follows the Runner as it clones the Repo and boots the Sandbox.

</Steps>

Every Session runs the same agent, on whichever of your Models you pick. [Switch the Model](/guides/manage-a-session/#choose-the-model-and-thinking-level) at any time, to any of yours.

## Prompt it while others watch

Everyone with access to the Repo can prompt the Session, steer and stop it. It spends the Creator's accounts, whoever prompts. The agent reads each prompt with its sender's name.

- **While the agent works**, new prompts wait in the [Prompt queue](/reference/glossary/#prompt-queue) and run in order.
- **To get a queued prompt in now**, press **Steer** on it. The agent reads it at its next step, usually after the current tool call, and the transcript marks it **Steered in**.
- **To stop the Turn**, press **Stop** in the prompt box.

The agent never asks for permission to run a tool. Everything it runs stays in the Session's Sandbox: see [Security model](/concepts/security-model/).

### Read a Turn's footer

Each Turn ends with a footer: how long it took, the tokens in and out, and a cost in US dollars when its Model reports one. A Turn that ran on another Model than the Session's current one names it. The Session's header shows what the main conversation has cost so far.

## Follow the Plan

For work of several steps, the agent keeps a checklist, the Plan. It shows above the prompt box, live for everyone: steps are pending, in progress or done. A [Thread](/guides/reply-in-a-thread/) starts with the Plan as it was where it forked, then keeps its own.

## Compact the conversation

The agent summarizes a conversation's older messages on its own as it nears its Model's context limit, so a Session doesn't run out. To do it now, choose the compaction action in the Session's actions menu, and say what to keep, if you like. A divider in the transcript marks where it happened. A Thread has its own compaction action.

## Answer the agent's questions

When the agent asks a question, the Session's row gets an amber dot and its header says **Waiting on an answer**. A card above the prompt box asks the questions one at a time.

![A question card: "Which date library should the web UI use?", with three options, Bob's pick on Luxon, and a Something else field.](../../../assets/screenshots/question.png)

- Click an option, or press its number.
- Type your own answer in **Something else** and press Enter.
- Press **Skip** to leave a question unanswered.

Anyone in the Session can answer, and everyone sees the picks. The first answer is the one the agent reads. Only the main conversation's agent asks questions: Threads and subagents don't. The answers go to the agent after the last question. To reply in your own words, type in the prompt box (**Or reply directly…**) and press **Reply**.

## Use the terminal

**Terminal**, in the prompt box's bar, opens a plain shell in `/workspace`. Use it for what the chat doesn't cover: your own commands, Esc and Ctrl-C. It isn't the agent's screen: the agent has none.

Everyone in the Session sees the same shell and can type into it. **Fit to my window** sets its size to yours. The shell starts again if you exit it, and the agent keeps working.

## What the agent can use

The agent runs in `/workspace`, the Repo's checkout. Settings on the Runner's machine never apply.

- **Instructions.** The Repo's `AGENTS.md` and `CLAUDE.md` at its root, read live, so an edit reaches the next request. Nested ones are listed for the agent to read where it works.
- **Skills.** Those in `.agents/skills`, `.claude/skills` and `.pi/skills`, by name and description.
- **MCP servers.** The ones the Hub adds to its Sessions: see [Add a remote MCP server](/guides/add-a-remote-mcp-server/). A Repo's `.mcp.json`, hooks, plugins and Claude Code settings don't apply.

## Get the work out

Ask the agent to commit, push and open a pull request:

```text
Commit this, push the branch and open a pull request.
```

The agent uses `git` and `gh` once the Hub has its GitHub App: see [Git from Sessions](/concepts/git-from-sessions/).

:::caution
Until it's pushed, the work exists only in the Session's Workspace on the Runner. If that machine's disk is lost, so is the work.
:::
