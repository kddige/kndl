kndl has three parts: a Hub that people sign in to, Runners that run Sessions, and a Sandbox for each Session.

<ArchitectureDiagram />

- **The Hub** is one Bun process with a SQLite database. It keeps every Session, its history and its [Prompt queue](/reference/glossary/#prompt-queue), and relays prompts and replies between people and Runners. It also holds each person's [Connected providers](/reference/glossary/#connected-provider), and carries their Sessions' model calls.
- **A Runner** is a machine that runs Sessions. It connects out to the Hub over a WebSocket, so the Hub never needs to reach it.
- **A Sandbox** is a microVM on a Runner, one per Session. The Session's agent runs there, with every tool and command it starts.

Browsers, Runners and each Session's mod talk to the Hub, never to each other.

## A Session, end to end

A Session is one body of agent work on one Repo. When someone starts one:

1. The Hub records it and picks a Runner, or the one you chose.
2. The Runner clones the Repo into the Session's Workspace, on its Work branch.
3. The Runner boots the Sandbox from the Repo's [Environment](/concepts/environments/), with the Workspace mounted at `/workspace`.
4. It starts the Session's agent, the [durable agent](/reference/glossary/#durable-agent), in the Sandbox. The agent connects the Session to the Hub.
5. A prompt from anyone in the Session goes to the Hub, into the Session's Prompt queue. When the agent is idle, the Hub hands it the next prompt.
6. As the agent works, it reports its text, each tool call, each subagent and its Plan to the Hub. The Hub masks secrets and sends it to everyone in the Session.

The Hub holds the queue, so anyone can send prompts while a Turn runs. They run in order, one Turn at a time in the main conversation. A [Thread](/guides/reply-in-a-thread/) forks off an answer and runs beside it, outside the queue.

## The agent in the Sandbox

The agent runs inside the Sandbox, so its tools run where it runs ([ADR 0013](/contributing/decisions/0013-claude-code-runs-in-the-sandbox/)). It's one headless Node.js program built on Pi Durable, the same for every Model. Its conversation lives in a SQLite database on the Session's disk, so a Turn cut off by a restart goes on where it stopped.

- **It never asks for approval.** The Sandbox is the boundary, not a prompt ([ADR 0004](/contributing/decisions/0004-the-sandbox-is-the-security-boundary/)).
- **Model calls go through the Hub.** The agent sends each one to the Hub's Gateway, on the Session token, and the Gateway sends it on to the Provider with the Creator's credential. The credential stays on the Hub. See the [security model](/concepts/security-model/#the-gateway).
- **Claude's Models run through Claude Code.** For a Claude Model, the agent runs Claude Code in the Sandbox as the model alone, with the agent's own tools, on the Creator's setup token. Claude Code talks to Anthropic directly. See [The Creator's token](/concepts/security-model/#the-creators-token).
- **The agent reaches the Hub through the Runner.** The Runner's mod relay passes its calls, model calls and MCP traffic to the Hub, so the Sandbox needs no route to it.
- **Its versions are pinned.** Each kndl version runs one tested Pi Durable, on one Node.js, and one tested Claude Code, which the Runner downloads once and shares with every Sandbox.

Beside the main conversation, a Session can hold [Threads](/guides/reply-in-a-thread/), each on a Model of its own, and [subagents](/guides/work-with-subagents/). The agent keeps a Plan for each conversation, and summarizes a conversation's older messages when it nears its Model's context limit.

## Sandboxes are disposable

A Session's data lives on disks that outlive its Sandbox ([ADR 0006](/contributing/decisions/0006-workspace-on-host-sandbox-disposable/)). The Runner can stop a Sandbox when the Session sleeps, or replace it with a newer one, and nothing is lost.

| What                                  | Where it lives                                                   |
| ------------------------------------- | ---------------------------------------------------------------- |
| Source code                           | The Workspace, a directory on the Runner mounted at `/workspace` |
| `node_modules` and package caches     | Disks of the Session's own, faster than the host mount           |
| Docker's data                         | Its own disk, when the Environment turns Docker on               |
| The agent's conversation and settings | Its own disk, so a woken Session carries on                      |

Only what git in the Sandbox pushes leaves the Runner.

## Several people, one Session

The person who started a Session is its Creator. It runs on their Connected providers and commits as them. Everyone with access to the Repo on GitHub drives it on those accounts.

- **Everyone drives.** Anyone in the Session can prompt it, steer and cancel queued prompts, answer the agent's questions, and stop Turns and subagents. They can also start and post in Threads, compact a conversation, switch the model, sleep, wake, restart, rename, delete and restore it, and set Keep awake.
- **The accounts are the Creator's.** Every Turn spends their Connected providers and Claude credential, whoever prompted it.
- **One terminal.** The **Terminal** is a plain shell in the Sandbox that everyone in the Session sees and types into.
- **Everyone can look.** Anyone with access can follow the Session live or Archived, see its Attachments, and [forward its ports](/guides/forward-a-sessions-ports/).

## What runs where

|                                                           | Hub's machine           | Runner's machine              | Sandbox                                                                                    |
| --------------------------------------------------------- | ----------------------- | ----------------------------- | ------------------------------------------------------------------------------------------ |
| Sessions, history, Prompt queues, Environments, Variables | Yes, in SQLite          |                               |                                                                                            |
| The GitHub App's private key                              | Yes                     |                               |                                                                                            |
| People's Connected providers                              | Encrypted               |                               |                                                                                            |
| People's Claude credentials                               | Encrypted               | Passed on as a Session starts | The Creator's, in the agent's environment                                                  |
| The mod relay                                             |                         | Yes                           |                                                                                            |
| The Workspace                                             |                         | Yes                           | Mounted at `/workspace`                                                                    |
| The agent, Claude Code, and your Repo's code running      |                         |                               | Yes                                                                                        |
| A GitHub token for the Session's Repo                     |                         |                               | Yes, in memory ([ADR 0010](/contributing/decisions/0010-the-sandbox-gets-a-github-token/)) |
| The Environment's Variables                               | Encrypted, if Sensitive | In memory, while needed       | Yes                                                                                        |

For the parts in more depth, see [Inside kndl](/contributing/internals/).
