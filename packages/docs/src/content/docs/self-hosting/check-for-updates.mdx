See from the web UI whether a newer kndl is out, and update the Hub to it.

The Hub checks kndl's repository on GitHub when it starts and every 6 hours. Its Owner sees what it found on the **Hub** page ([ADR 0028](/contributing/decisions/0028-the-owner-updates-the-hub-from-the-web/)).

## What you need

- To be the Hub's [Owner](/self-hosting/let-people-in/#become-the-owner). Members don't see the page or its banner.
- A Hub [installed](/self-hosting/install/) and run as kndl's service. A Hub run from a checkout with `bun run hub` doesn't check, and has no **Hub** page.

## Open the Hub page

In the sidebar, under **People**, open **Hub**. It shows:

- **Version:** the Release the Hub runs, or its commit on `dev`.
- **Channel:** `stable`, `dev`, or **Pinned to** the ref `--ref` pinned.
- **Last checked:** when the Hub last reached GitHub, and the error if its latest check failed.

Press **Check now** to check at once, after a Release is cut.

## Read what changed

What counts as newer follows the Hub's [Channel](/self-hosting/update/#what-you-get):

| Channel  | Offered                                  | The page shows                                           |
| -------- | ---------------------------------------- | -------------------------------------------------------- |
| `stable` | A Release newer than the Hub's           | The notes of each newer Release, newest first            |
| `dev`    | `main`'s head, once it is past the Hub's | How many commits behind, and the titles of the newest 50 |
| Pinned   | Nothing                                  | The ref the Hub is pinned to                             |

**Compare on GitHub** opens the changes on GitHub, and **On GitHub** a Release's own page.

A Hub on `stable` at a commit no Release has reached, as after switching from `dev`, is offered only a Release that includes its commit.

## Update the Hub

<Steps>

1. On the **Hub** page, under **Update**, press **Update**.

2. Confirm with **Update**. If Sessions are running, **Update now** is there too: it stops their running Turns at once rather than letting them end.

</Steps>

The Hub runs [`kndl update`](/self-hosting/update/) on its machine, outside its own service. **Latest update** shows each step, such as **Updating… Building the web UI**. While the Hub restarts, the page shows **Updating… Hub restarting** and reconnects on its own. Then it shows **Updated to 2026.10.4**.

The Runners follow the Hub's commit. Each lets its running Turns end, for up to ten minutes, then updates. While they wait, **Update now** under **Latest update** stops their Turns at once.

If a step fails, or the Hub doesn't come back healthy, the update goes back to the commit the Hub ran. The page shows **Update rolled back**, or **Update failed** if going back failed too, with the error and the end of the update's log.

Only one update runs at a time, from the web or the CLI. An update run with `kndl update` on the Hub's machine shows under **Latest update** too.

## Switch Channels

Next to **Channel**, press **Switch to dev** or **Switch to stable**, and confirm.

- **To `dev`:** the Hub updates to the head of `main` at once.
- **To `stable`:** the Hub moves to the latest Release only if it's newer than the Hub's commit. Otherwise it stays, and the page says `On stable. You'll move at the next Release newer than this commit.`

On a pinned Hub, press **Follow stable** or **Follow dev**. That unpins the Hub, after a confirmation.

## The banner

While an update exists, a banner across the web UI says so, such as **kndl 2026.10.4 is out**. **See what's new** opens the **Hub** page.

**Dismiss** hides it in this browser until the Hub finds another update: a newer Release on `stable`, or new commits on `main` on `dev`.
